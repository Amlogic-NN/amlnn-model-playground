# Mobilenet

This example runs Mobilenet with AMLNN. The full flow is:

1. Prepare or download an ONNX/TFLite model.
2. 
3. Convert the ONNX/TFLite model to an ADLA model.
4. Run the Python demo with the ADLA model.
5. Run the C++ (Linux/Android) demo with the ADLA model.
6. Check Classification results.

## Directory Layout

```bash
examples/mobilenet/
├── cpp/               # C++ demo and build scripts
├── input/             # Input images for demo
├── model/             # Put ONNX, TFLite, and ADLA models here
└── py/                # Python conversion and demo scripts
```

## 2. Convert ONNX/TFLite To ADLA

Run the ADLA export script from `examples/mobilenet/py`:

```bash
cd examples/mobilenet/py
python export_adla.py \
  --model ../model/mobilenet_v2.onnx \
  --dataset-path ../../../resource/classification_subset.txt \
  --target-platform 007 \
  --output-dir ../model
```

| Parameter           | Description                                                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `--model`           | Path to the input `.onnx` or `.tflite` model.                                                                                            |
| `--dataset-path`    | (Optional) Path to a `.txt` file containing the input paths used for quantization calibration. Required for `w8a8` and `w8a16 (i16)`.[1] |
| `--target-platform` | Target platform ID. See the full list of supported platforms [**HERE**](../../docs/mapping.md).                                          |
| `--output-dir` | (Optional) Directory where the generated `.adla` model will be saved. Defaults to `../model`. |                                   |

> **[1] Quantization dataset note**
>
> A calibration dataset is **not required** when using `activation_dtype="f16"`, such as `w8a16 (f16)` or `w16a16 (f16)`. Set this explicitly in the `amlnn.config()` call.
>
> If no dataset is provided, AMLNN generates random calibration data instead of failing, which can severely degrade model accuracy.
>
> `activation_dtype` does not apply to `w8a8`.

After conversion, the expected model path is:

```text
examples/mobilenet/model/mobilenet_v2_w8a8.adla
```

## 3. Supported Input Formats

Both the Python and C++ MobileNet inference demos support standard image files, raw image text files, and direct model-input tensor files.

| Format                          | Description                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `.jpg`, `.jpeg`, `.png`, `.bmp` | Standard image files processed through the normal MobileNet preprocessing pipeline.                                             |
| `.txt`                          | Raw BGR `uint8` image pixel values stored as text. *The file must NOT contain shape header or metadata.*                               |
| `.bin`                          | Final preprocessed model input tensor stored in raw binary form. Passed directly to inference without additional preprocessing. |
| `.qtxt`                         | Final preprocessed model input tensor stored as text. Passed directly to inference without additional preprocessing.            |

### Standard Image Inputs

Standard image files use the normal MobileNet preprocessing flow:

```text
.jpg/.jpeg/.png/.bmp
    -> image loading
    -> resize to model input resolution
    -> BGR to RGB
    -> normalize
    -> quantize if required
    -> inference
```

### Raw `.txt` Image Input

A `.txt` file represents raw BGR `uint8` image pixel values ranging from `0` to `255`.

The file contains **only pixel values** and does not include a shape header or other metadata. The image shape is assumed to match the model input dimensions in `H x W x 3` format.

Before processing, the demo checks the total number of values in the `.txt` file against the expected number of input image elements:

```text
H x W x 3
```

> **Note:** The `.txt` file must already contain the expected number of pixels for the model input resolution. It should not include a shape header. If the number of values does not match the expected `H x W x 3` size, the input is skipped.

### Direct `.bin` and `.qtxt` Model Inputs

The `.bin` and `.qtxt` formats contain the final model input tensor after preprocessing and quantization.

They contain no dimensions, shape headers, or other metadata.

* `.bin` stores the tensor in raw binary form.
* `.qtxt` stores the same tensor values as text.

The tensor is read using the model input shape and data type reported by AMLNN and is passed directly to inference.

No image loading, resizing, RGB conversion, normalization, or quantization is performed for these direct tensor formats.

The supported tensor types include `float32`, `int8`, `uint8`, and `int16` where applicable.

### Generate Test Inputs

A separate input-generation utility, `generate_inputs.py`, can be used to create `.txt`, `.bin`, and `.qtxt` test inputs from standard image files.

The utility accepts `.jpg`, `.jpeg`, `.png`, and `.bmp` images as source inputs. It does not read `.txt`, `.bin`, or `.qtxt` files as source inputs.

The ADLA model is loaded only to obtain the input tensor dimensions, scale, zero point, and tensor type. The utility does not perform inference.

For each source image, the utility generates three files:

* `.txt`: Contains the original raw BGR image pixels as text with no header or shape metadata. The `.txt` file can only be used by the inference demo if the source image dimensions already match the model input dimensions.
* `.bin`: Contains the final preprocessed and quantized model input tensor in binary format.
* `.qtxt`: Contains the same final model input tensor as `.bin`, but stores the tensor values as text.

The generation flow is:

```text
input image
    |
    +-> original raw BGR pixels
    |       -> .txt
    |
    +-> MobileNet preprocessing
            -> quantization if required
                    |
                    +-> .bin
                    |
                    +-> .qtxt
```

Run the utility from `examples/mobilenet/py`:

```bash
cd examples/mobilenet/py

python generate_inputs.py \
    --adla ../model/mobilenet_v2_w8a8.adla \
    --image-dir ../input \
    --output-dir generated_inputs
```

Argument Descriptions:

| Argument       | Description                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `--adla`       | Path to the compiled MobileNet model in `.adla` format. The model is loaded only to obtain its input tensor information.  |
| `--image-dir`  | Directory containing source `.jpg`, `.jpeg`, `.png`, or `.bmp` images to convert.                                         |
| `--output-dir` | (Optional) Directory where the generated `.txt`, `.bin`, and `.qtxt` files will be saved. Defaults to `generated_inputs`. |

For each processed image, the utility generates:

```text
generated_inputs/
├── test_image.txt
├── test_image.bin
└── test_image.qtxt
```

> **Note:** Because `.txt` contains no shape metadata, the original source image must already match the MobileNet model input dimensions for the generated `.txt` file to be usable by the inference demo. The `.bin` and `.qtxt` outputs are not affected by the original image dimensions because the generator preprocesses them to the model input size.

## 4. Run Python Demo

### Prerequisites

* Python 3.10
* Required packages: `amlnn`

### Install Dependencies

```bash
pip install amlnn_edge_toolkit_lite-1.0.0-cp310-cp310-linux_aarch64.whl
```

### Run on Device

```bash
python mobilenet_inference.py \
    --adla ../model/mobilenet_v2_w8a8.adla \
    --labels ../labels.txt \
    --image-dir ../input
```

Argument Descriptions:

| Argument      | Description                                             |
| ------------- | ------------------------------------------------------- |
| `--adla`      | Path to the compiled MobileNet model in `.adla` format. |
| `--labels`    | Path to `labels.txt`.                                   |
| `--image-dir` | Directory containing test images.                       |

The script will automatically process all supported input files (`.jpg`, `.jpeg`, `.png`, `.bmp`, `.bin`, `.txt`) in the specified image directory and save results to a `{model_name}_result` folder.

> **Note:** Do not place `labels.txt` inside the input directory because `.txt` files in the input directory are treated as model input files.

## 5. Run C++ Demo

### Build For Android

#### Prerequisites

* **Android NDK** (r27d recommended) installed on your system.
* **AMLNN Toolkit** downloaded and extracted.
* Prebuilt OpenCV located at `../../../dependency/opencv/` (relative to the script directory).

#### 1. Setup Environment

Export the paths to your NDK (the toolchain) and AMLNN (the neural network dependency) so the script can find them.

```bash
export ANDROID_NDK_PATH=/path/to/android-ndk-r27d
export AMLNN_HOME=/path/to/amlnn-toolkit/amlnn_runtime
```

#### 2. Build

Navigate to the C++ directory and run the build script.

```bash
cd examples/mobilenet/cpp

# Build for 64-bit (arm64-v8a) - Default
./build-android.sh

# Build for 32-bit (armeabi-v7a)
./build-android.sh -a armeabi-v7a
```

The executable will be generated in the build folder corresponding to the selected Android ABI:

* 64-bit: `build/android/arm64-v8a/mobilenet_demo`
* 32-bit: `build/android/armeabi-v7a/mobilenet_demo`

#### 3. Example Run

The following example uses the default 64-bit (`arm64-v8a`) build.

```bash
# Push executable and assets to device
adb shell "mkdir -p /data/local/tmp/"
adb push build/android/arm64-v8a/mobilenet_demo /data/local/tmp/
adb push ../model/mobilenet_v2_w8a8.adla /data/local/tmp/
adb push ../input /data/local/tmp/
adb push ../labels.txt /data/local/tmp/

# Run on device
adb shell
cd /data/local/tmp
chmod +x mobilenet_demo
export LD_LIBRARY_PATH=/vendor/lib64

# Usage: ./mobilenet_demo <model_path> <image_dir> <labels.txt>
./mobilenet_demo mobilenet_v2_w8a8.adla input/ labels.txt
```

> **Note:** For a 32-bit (`armeabi-v7a`) build, use `build/android/armeabi-v7a/mobilenet_demo` and the corresponding 32-bit library path. Replace `mobilenet_v2_w8a8.adla` with your actual model file name.

### Build For Linux

The Linux build process supports two distinct modes:

1. **Standard Linux cross-compilation** (default)
2. **Yocto SDK compilation**

#### Mode 1: Standard Linux Cross-Compile (Default)

##### Prerequisites

* A GCC Cross-Compiler toolchain (GCC 10.3 recommended).
* The toolchain's `bin/` folder must be added to your system's `PATH`.
* Prebuilt OpenCV located in the `dependency/opencv/` folder.
* `AMLNN_HOME` environment variable set.

##### 1. Setup Environment

Add your downloaded toolchain to your `PATH` and export the `AMLNN_HOME` variable so the script can find the compiler and neural network dependencies.

```bash
# Export the AMLNN path
export AMLNN_HOME=/path/to/amlnn-toolkit/amlnn_runtime

# For 64-bit (aarch64) builds, add the 64-bit toolchain to PATH:
export PATH=/path/to/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu/bin:$PATH

# OR for 32-bit (arm) builds, add the 32-bit toolchain to PATH:
export PATH=/path/to/gcc-arm-10.3-2021.07-x86_64-arm-none-linux-gnueabihf/bin:$PATH
```

##### 2. Build

```bash
cd examples/mobilenet/cpp

# Build for 64-bit (Default)
./build-linux.sh

# Build for 32-bit
./build-linux.sh -b 32
```

> **Optional Override:** If your compiler has a different prefix name (for example, `aarch64-linux-gnu` instead of `aarch64-none-linux-gnu`), you can override the default by setting the `GCC_COMPILER` variable:

```bash
GCC_COMPILER=aarch64-linux-gnu ./build-linux.sh
```

The executable will be generated in the build folder corresponding to the selected architecture:

* 64-bit: `build/linux/64/mobilenet_demo`
* 32-bit: `build/linux/32/mobilenet_demo`

#### Mode 2: Yocto/Debian/Armbian Build

##### 1. Prerequisites

* Yocto SDK installed.
* CMake Toolchain file available.
* Prebuilt OpenCV located in the `dependency/opencv/` folder.

##### 2. Setup Environment

```bash
# Export the AMLNN path
export AMLNN_HOME=/path/to/amlnn-toolkit/amlnn_runtime
```

##### 3. Build

```bash
cd examples/mobilenet/cpp

# Build for Yocto 64-bit (Default)
./build-linux.sh -m yocto -s /path/to/yocto_sdk_root -t /path/to/toolchain.cmake

# Build for Yocto 32-bit
./build-linux.sh -m yocto -b 32 -s /path/to/yocto_sdk_root -t /path/to/toolchain.cmake
```

> **Note:** You can also use the `YOCTO_SDK_ROOT` and `TOOLCHAIN_FILE` environment variables instead of passing the `-s` and `-t` flags.

The executable will be generated in the build folder corresponding to the selected architecture:

* 64-bit: `build/yocto/64/mobilenet_demo`
* 32-bit: `build/yocto/32/mobilenet_demo`

#### 3. Example Run

The following example uses the default 64-bit Linux build.

```bash
# Push executable and assets to device (adjust build path if using Yocto)
adb shell "mkdir -p /data/local/tmp/"
adb push build/linux/64/mobilenet_demo /data/local/tmp/
adb push ../model/mobilenet_v2_w8a8.adla /data/local/tmp/
adb push ../input /data/local/tmp/
adb push ../labels.txt /data/local/tmp/

# Run on device
adb shell
cd /data/local/tmp
chmod +x mobilenet_demo

# Usage: ./mobilenet_demo <model_path> <image_dir> <labels.txt>
./mobilenet_demo mobilenet_v2_w8a8.adla input/ labels.txt
```

> **Note:** Replace `mobilenet_v2_w8a8.adla` with your actual model file name. Adjust the executable path if using a 32-bit or Yocto build.

## 6. Results

### Performance Feedback

By setting the log level to `INFO`, the program provides runtime performance information after inference. The console output may include:

* **Hardware Information:** System and ADLA library versions.
* **Model Overview:** Input and output tensor configurations.
* **NPU Metrics:** Inference latency and DRAM bandwidth usage.

### Classification Output

For each input image, the program prints the Top-5 classification results with their respective scores.

Example:

```text
============================================================
Processing image 1/3: dog_224x224.jpg
============================================================
    Top-5 Results:
      1. Shih-Tzu              score=15.328343
      2. Pekinese              score=12.163782
      3. Lhasa                 score=11.570427
      4. Brabancon griffon     score=7.318048
      5. Dandie Dinmont        score=7.318048

============================================================
```
