# MobileCLIP

This example demonstrates image-text matching with AMLNN on Amlogic NPU platforms. It includes Python and C++ inference demos for vision and text encoder `.adla` models.

## Directory layout

```bash
examples/mobileclip/
├── cpp/                    # C++ demo and build scripts (Android / Linux)
│   └── src/                # mobileclip_demo source
├── input/                  # Demo input assets
├── model/                  # Place runtime .adla models here
└── py/                     # Python inference scripts
    ├── clip_tokenizer.py
    └── mobileclip_inference.py
```

## 1. Prerequisites

Place the vision and text encoder `.adla` models under `model/`.

Model IO conventions:


| Encoder | Input name | Input shape        |
| ------- | ---------- | ------------------ |
| Vision  | `image`    | `[1, 3, 256, 256]` |
| Text    | `text`     | `[1, 77]`          |


## 2. Run Python Demo

**Prerequisites:**

- Python 3.10+
- Required packages: `numpy`, `Pillow`, `amlnn`
- A tokenizer directory containing `vocab.json` and `merges.txt`

**Install dependencies example:**

```bash
pip install numpy Pillow amlnn_toolkit-1.0.0-cp312-cp312-linux_aarch64.whl
```

**Run on device:**

```bash
cd py

python mobileclip_inference.py \
  --vision-model ../model/vision.adla \
  --text-model ../model/text.adla \
  --tokenizer-dir /path/to/tokenizer \
  --image-path ../input/test.jpg \
  --texts "a red bus" "a red handbag" "a blue jacket"
```


| Argument          | Description                                                             |
| ----------------- | ----------------------------------------------------------------------- |
| `--vision-model`  | Path to vision encoder `.adla` model                                    |
| `--text-model`    | Path to text encoder `.adla` model                                      |
| `--tokenizer-dir` | Directory containing `vocab.json` and `merges.txt`                      |
| `--image-path`    | Optional input image path. If omitted, the script prompts interactively |
| `--texts`         | Optional text descriptions to compare                                   |
| `--logit-scale`   | Optional logit scale, default `100.0`                                   |
| `--runtime-mode`  | `native` or `nnserver`, default `native`                                |
| `--enable-perf`   | Enable AMLNN performance collection                                     |


If `--image-path` and `--texts` are omitted, the script enters interactive mode similar to the C++ demo.

## 3. Run C++ Demo

### Build For Android

**Prerequisites:**

- Android NDK (r27d recommended)
- AMLNN toolkit downloaded and extracted

**1. Setup environment:**

```bash
export ANDROID_NDK_PATH=/path/to/android-ndk-r27d
export AMLNN_HOME=/path/to/amlnn-toolkit/amlnn_runtime
```

**2. Build:**

```bash
cd examples/mobileclip/cpp

# Build for 64-bit (arm64-v8a) - Default
./build-android.sh

# Build for 32-bit (armeabi-v7a)
./build-android.sh -a armeabi-v7a
```

The executable will be generated at:

```text
build/android_arm64-v8a/mobileclip_demo
```

**Run:**

```bash
adb shell "mkdir -p /data/mobileclip"
adb push build/android_arm64-v8a/mobileclip_demo /data/mobileclip/
adb push ../model/vision.adla /data/mobileclip/models/
adb push ../model/text.adla /data/mobileclip/models/
adb push /path/to/tokenizer /data/mobileclip/tokenizer/
adb push ../input/000000004505.jpg /data/mobileclip/input/

adb shell
cd /data/mobileclip
chmod +x mobileclip_demo

# Usage:
# mobileclip_demo [options] <vision_model.adla> <text_model.adla> <tokenizer_dir> <image.jpg>
./mobileclip_demo \
  models/vision.adla \
  models/text.adla \
  tokenizer/ \
  input/000000004505.jpg
```

Optional flags:


| Flag                  | Description                                              |
| --------------------- | -------------------------------------------------------- |
| `--neon true/false`   | Enable/disable NEON for ADLA soft ops (default: true)    |
| `--openmp true/false` | Enable/disable OpenMP for ADLA soft ops (default: false) |
| `--openmp-num N`      | OpenMP thread count, default `2`                         |
| `--profiling`         | Enable performance profiling output                      |


### Build For Linux

The Linux build supports two modes: **standard cross-compilation** (default) and **Yocto SDK compilation**.

#### Mode 1: Standard Linux Cross-Compile (Default)

**Prerequisites:**

- A GCC cross-compiler toolchain (GCC 10.3+ recommended)
- The toolchain `bin/` directory added to `PATH`
- `AMLNN_HOME` environment variable set

**1. Setup environment:**

```bash
export AMLNN_HOME=/path/to/amlnn-toolkit/amlnn_runtime

# For 64-bit (aarch64) builds:
export PATH=/path/to/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu/bin:$PATH

# For 32-bit (arm) builds:
export PATH=/path/to/gcc-arm-10.3-2021.07-x86_64-arm-none-linux-gnueabihf/bin:$PATH
```

**2. Build:**

```bash
cd examples/mobileclip/cpp

# Build for 64-bit (default)
./build-linux.sh

# Or explicitly:
./build-linux.sh -b 64
./build-linux.sh -a aarch64

# Build for 32-bit
./build-linux.sh -b 32
./build-linux.sh -a armhf
```

If your compiler uses a different prefix, override it with `GCC_COMPILER`:

```bash
GCC_COMPILER=aarch64-linux-gnu ./build-linux.sh
```

The executable will be generated at:

```text
build/linux/64/mobileclip_demo
build/linux/32/mobileclip_demo
```

#### Mode 2: Yocto Build

**Prerequisites:**

- Yocto SDK installed
- CMake toolchain file available

**Build:**

```bash
export AMLNN_HOME=/path/to/amlnn-toolkit/amlnn_runtime

cd examples/mobileclip/cpp

# Build for Yocto 64-bit (default)
./build-linux.sh -m yocto -b 64 -s /path/to/yocto_sdk_root -t /path/to/toolchain.cmake

# Build for Yocto 32-bit
./build-linux.sh -m yocto -b 32 -s /path/to/yocto_sdk_root -t /path/to/toolchain.cmake
```

You can also set `YOCTO_SDK_ROOT` and `TOOLCHAIN_FILE` instead of passing `-s` and `-t`.

The executable will be generated at:

```text
build/yocto/64/mobileclip_demo
build/yocto/32/mobileclip_demo
```

**Run on Linux device:**

Copy the binary, models, tokenizer directory, and input image to the target device, then run:

```bash
./mobileclip_demo \
  models/vision.adla \
  models/text.adla \
  tokenizer/ \
  input/000000004505.jpg
```

Optional flags are the same as the Android demo (`--neon`, `--openmp`, `--openmp-num`, `--profiling`).
